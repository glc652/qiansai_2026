# AI-RehabBand 智能康复臂带创新性、挑战性与作品价值

## 1. 总体定位

AI-RehabBand 智能康复臂带不是单一传感器显示装置，而是一套面向上肢康复训练的可穿戴边缘智能评估系统。系统由上臂端、手腕端和 Web 康复分析端组成，通过双 IMU 相对姿态计算、肌电边缘 AI、动作状态机、训练评分、无线通信和历史数据分析，形成从训练采集到反馈评估的闭环。

答辩时可以先用这句话概括：

> 我们的创新点不在某一个单独模块，而在于把可穿戴感知、端侧评估、肌电 AI、双端本地交互和 Web 数据分析连接成了一个完整康复训练闭环。

## 2. 创新性

### 2.1 从单点姿态显示升级为双 IMU 相对姿态评估

普通单 IMU 或运动手环只能反映某一个部位相对空间的姿态变化，容易受到身体整体移动、佩戴位置变化和手臂代偿动作影响。AI-RehabBand 在上臂端和手腕端分别布置 IMU，通过两端姿态差计算肘关节屈伸、前臂旋转、手臂外展和肩部上举等动作角度。

创新点：

- 关注的是关节相对运动，而不是单个传感器角度。
- 更接近康复训练中关心的关节活动范围。
- 能降低身体整体移动造成的误判。

答辩话术：

> 我们不是只看某个模块在空间里的角度，而是看上臂和手腕之间的相对变化。康复训练关心的是关节活动范围，所以双 IMU 相对姿态比单点传感器更贴近康复评估需求。

### 2.2 从动作计数升级为训练质量评估

系统不只记录“做了几次”，还结合动作角度、目标次数、最大角度、平均角度、完成度、幅度和综合评分，形成训练质量评估。

创新点：

- 将训练过程从简单计数变成可量化评分。
- 区分“完成了动作”和“动作质量是否达标”。
- 支持训练结果进入历史记录和趋势分析。

答辩话术：

> 单纯计数只能知道患者做了几次，但不能说明动作幅度是否足够、质量是否稳定。我们的评分把次数、角度和完成度结合起来，让训练结果更接近康复反馈。

### 2.3 肌电边缘 AI 判断主动发力状态

系统在上臂端集成肌电采集和边缘 AI 推理。肌电模型基于 4469 条标注样本训练，输入 6 个基线归一化特征，输出 relax、weak、active 三类肌肉参与状态，并导出 C 模型部署到 STM32。

创新点：

- 不是简单阈值判断，而是完成了数据采集、特征工程、模型训练、评估报告和 C 代码部署流程。
- 在 MCU 端完成肌电参与状态推理，减少对上位机或云端依赖。
- 用于补充“患者有没有主动发力”这一康复训练关键问题。

可讲数据：

| 指标 | 数值 |
|---|---:|
| 肌电数据总样本数 | 4469 条 |
| relax 样本 | 1489 条 |
| weak 样本 | 1489 条 |
| active 样本 | 1491 条 |
| 测试集样本数 | 1118 条 |
| 总体准确率 | 78.26% |
| relax 类 F1 | 96.64% |
| 输入特征 | 6 个基线归一化特征 |

答辩话术：

> 肌电部分不是一个阈值开关，而是一个边缘 AI 模型。我们完成了从肌电数据采集、特征提取、随机森林训练、评估报告到 C 模型导出的 TinyML 流程，并把模型集成到 STM32 上臂端实时运行。

### 2.4 肌电 AI 输出结合屈肘角度进行框定

肌电信号容易受电极接触、佩戴松紧、皮肤阻抗和瞬时噪声影响。如果直接使用肌电模型输出，可能出现动作未进入有效区间却显示强发力的情况。因此系统将肌电 AI 结果与屈肘角度、动作阶段进行二次约束。

创新点：

- 肌电模型回答“是否有肌肉参与”。
- IMU 角度回答“动作是否进入有效区间”。
- 两者融合后形成更符合康复动作逻辑的判断。

答辩话术：

> 我们没有把 AI 模型当成黑箱直接输出，而是给它加上康复动作约束。肌电判断主动发力，IMU 判断动作幅度，两者结合后才能形成训练评价，这比单独看肌电或单独看角度更可靠。

### 2.5 双端本地界面 + Web 三层可视化

当前代码中，上臂端是完整 LVGL 主控界面，包含首页、动作选择、准备校准、训练页、结果页、自由训练、历史记录、数据分析、设置和断连页。手腕端是轻量随身反馈界面，包含首页、健康监测、训练中、等待上臂选择、蓝牙断连和设置弹窗。Web 端负责大屏实时展示、历史记录和康复分析。

创新点：

- 上臂端负责完整训练流程和数据展示。
- 手腕端负责近身反馈、连接状态和健康入口。
- Web 端负责大屏分析和长期追踪。
- 三层界面分工明确，不是简单重复显示。

答辩话术：

> 上臂端管训练流程，手腕端管随身反馈，Web 端管数据分析。这样的三层可视化设计更符合真实穿戴场景：患者看手腕端，操作者看上臂端，评委或康复师看 Web 大屏。

### 2.6 手写 MQTT 报文链路

上臂端通过 ESP8266 接入 WiFi，STM32 端手动构造 MQTT 3.1.1 CONNECT / PUBLISH 报文，将训练数据和健康数据上传到 Web 后端。

创新点：

- 不完全依赖重型 MQTT 库，降低嵌入式端资源占用。
- 可以控制报文大小、发送周期和上传字段。
- 展示了对底层通信协议和 MCU 资源约束的理解。

答辩话术：

> 我们没有简单调用完整 MQTT 库，而是在 STM32 端按 MQTT 3.1.1 协议构造 CONNECT 和 PUBLISH 报文，再通过 ESP8266 的 TCP 链路发送。这样更轻量，也更适合资源受限的嵌入式设备。

### 2.7 HTTP 时间同步 + RTC 本地走时

设备通过 HTTP 从 Web 端获取时间，写入 STM32 RTC，后续由 RTC 本地走时，避免频繁联网取时间阻塞训练流程。

创新点：

- 保证设备时间和 Web 端记录时间一致。
- 避免频繁 HTTP 请求影响训练实时性。
- 体现嵌入式系统对阻塞风险和时间一致性的处理。

答辩话术：

> 时间同步不是一直访问网络，而是先通过 HTTP 获取 Web 端时间并写入 RTC，后续由 RTC 本地运行。这样兼顾时间一致性和训练实时性。

## 3. 挑战性

### 3.1 多任务实时调度挑战

上臂端同时运行 IMU 姿态解算、肌电采样、LVGL 界面、语音模块、无线接收、WiFi 上传、振动提示等任务。手腕端同时运行 IMU 采样、健康检测、无线发送、LVGL 界面和按键交互。

挑战点：

- 传感器采样不能被显示刷新或 WiFi 上传阻塞。
- LVGL 刷新和 SPI LCD 传输会占用一定时间。
- 无线通信和调试打印如果过多，会影响姿态角稳定。
- 多任务下浮点运算需要正确保存 FPU 上下文。

答辩话术：

> 最大挑战之一是多任务并行稳定运行。单独点亮屏幕或单独读 IMU 不难，难的是 IMU、肌电、无线、WiFi、屏幕和 Web 上传同时工作时，训练逻辑仍然保持稳定。

### 3.2 双端姿态同步挑战

双 IMU 相对姿态依赖上臂端和手腕端数据同步。无线链路会存在延迟、丢包或短时断连，佩戴动作也会产生抖动。

挑战点：

- 两端采样时间不完全一致。
- 无线链路会带来延迟和新旧数据混合风险。
- 上臂端和手腕端姿态都需要稳定校准。
- 相对角度计算要避免因为某一端数据失效造成误判。

答辩话术：

> 双 IMU 的价值在于能计算相对姿态，但它的难点也在同步。我们需要保证上臂和手腕两端的数据尽量新鲜，并在断连或数据无效时给出提示，避免错误训练反馈。

### 3.3 可穿戴佩戴误差挑战

臂带和手腕端的佩戴位置、松紧程度、初始姿态都会影响 IMU 和肌电信号。

挑战点：

- 不同用户佩戴位置不同。
- 训练过程中臂带可能轻微滑动。
- 初始姿势不一致会导致角度零点偏差。
- 肌电电极接触质量会影响信号稳定性。

答辩话术：

> 可穿戴设备不是实验台固定传感器，佩戴误差是必须面对的问题。当前原型通过零位校准、相对姿态和动作状态机降低影响，后续还可以加入个体化校准和佩戴提示。

### 3.4 肌电弱信号处理挑战

肌电是微弱生物电信号，对电极接触、皮肤状态和噪声非常敏感。

挑战点：

- 静息基线会随人和佩戴状态变化。
- weak 和 active 是连续过渡状态，边界不明显。
- 单次采样可能出现跳变。
- 模型泛化需要更多受试者和更多佩戴状态数据。

答辩话术：

> 肌电模型当前是原型数据集验证，不说医疗级准确率。它的价值在于补充主动发力判断，并通过角度框定减少误判。后续重点是扩大数据集和做个体化校准。

### 3.5 嵌入式界面资源挑战

上臂端和手腕端都使用 LVGL 和 ST7789 显示，界面需要兼顾美观、可读性和刷新性能。

挑战点：

- 屏幕尺寸有限，信息不能堆太多。
- 训练页要实时更新角度、次数、进度条和曲线。
- 手腕端需要保持轻量，避免影响 IMU 和健康数据任务。
- 中英文、图标、字体和页面切换都占用 Flash / RAM。

答辩话术：

> 双端界面不是简单做几个按钮。上臂端要承载完整训练数据，手腕端要保持轻量和快速反馈，这需要在信息密度、刷新性能和嵌入式资源之间做平衡。

### 3.6 通信链路和 Web 对接挑战

系统既有上臂和手腕之间的无线串口通信，也有上臂端到 Web 后端的 WiFi / MQTT 上传。

挑战点：

- 双端无线数据需要校验和状态判断。
- MQTT 上传字段要尽量短，避免报文过长影响稳定性。
- Web 端要解析训练、健康、页面状态等不同类型数据。
- 训练数据和健康数据上传周期不同，需要分主题、分节奏处理。

答辩话术：

> 通信不是单纯把串口数据打印出去，而是要区分训练数据、健康数据和页面状态，同时控制上传周期和数据长度，保证设备端训练流程不被通信阻塞。

## 4. 作品价值

### 4.1 对患者的价值

患者居家训练时，最大问题是缺少即时反馈。AI-RehabBand 可以将动作角度、次数、完成度和评分可视化，让患者知道自己是否完成训练。

价值点：

- 帮助患者减少盲目训练。
- 让训练过程有即时反馈。
- 通过手腕端提示提升佩戴端可用性。
- 通过历史记录增强训练持续性。

答辩话术：

> 对患者来说，这个系统最大的价值是把“凭感觉训练”变成“看得见的训练反馈”。患者能知道动作有没有做到位、次数有没有完成、训练结果有没有进步。

### 4.2 对康复师的价值

康复师需要了解患者长期训练情况，而不是只看某一次动作表现。

价值点：

- 提供训练次数、角度、评分和历史趋势。
- 帮助识别薄弱动作。
- 为训练方案调整提供数据参考。
- 可扩展为远程康复随访工具。

答辩话术：

> 对康复师来说，它提供的是训练过程数据，而不是一次性结果。后续可以根据历史趋势调整训练方案，减少完全依赖人工观察。

### 4.3 对居家康复和远程随访的价值

居家康复缺少专业设备和现场指导，远程随访又需要数据支撑。AI-RehabBand 将训练过程记录下来，具备向居家康复和远程康复平台扩展的基础。

价值点：

- 支持本地设备端训练反馈。
- 支持 Web 端历史记录和趋势分析。
- 后续可升级数据库或云平台。
- 适合向家庭健康管理、养老和康复机构场景扩展。

答辩话术：

> 它目前是比赛原型，但技术路径已经覆盖居家康复产品的关键环节：可穿戴采集、端侧评估、无线上传、历史追踪和康复建议。

### 4.4 对工程实践的价值

作品覆盖嵌入式、传感器、AI 模型、无线通信、图形界面和 Web 后端，属于软硬件一体化系统。

价值点：

- 双 STM32U575 嵌入式协同。
- IMU 姿态解算和动作状态机。
- 肌电数据采集与 TinyML 部署。
- LVGL 双端本地界面。
- ESP8266 / MQTT / HTTP 通信链路。
- Web 实时展示和历史分析。

答辩话术：

> 这个作品不是单片机小实验，也不是单纯 App。它把嵌入式实时任务、传感器采集、边缘 AI、通信协议、图形界面和 Web 平台都串起来了，体现的是完整系统工程能力。

### 4.5 对比赛展示的价值

比赛现场需要评委快速看到作品完成度。AI-RehabBand 可以通过前臂旋转、肘关节屈伸、上臂端界面、手腕端界面和 Web 大屏形成完整演示链路。

推荐展示顺序：

1. 展示上臂端首页和动作选择，说明它是训练主控屏。
2. 展示手腕端首页和连接状态，说明它是随身反馈屏。
3. 演示前臂旋转，突出双 IMU 相对姿态。
4. 演示肘关节屈伸，突出角度、次数、完成度和肌电 AI。
5. 展示结果页、历史记录和 Web 康复分析，突出闭环价值。

答辩话术：

> 现场演示我会优先展示两条最稳定、最能体现技术完整性的链路：前臂旋转展示双 IMU 相对姿态，肘关节屈伸展示角度评估和肌电 AI 融合，最后用历史记录和 Web 分析说明它不是一次性演示，而是康复训练闭环。

## 5. 可以放到 PPT 的精简版

### 创新性

- 双 IMU 相对姿态评估关节活动范围，而不是单点角度显示。
- 肌电边缘 AI 判断 relax / weak / active 主动发力状态。
- 肌电 AI 输出结合屈肘角度和动作阶段进行框定。
- 上臂端、手腕端、Web 端形成三层可视化分工。
- STM32 端手写 MQTT 报文，实现轻量化数据上传。
- 历史记录和康复分析让训练过程可追踪。

### 挑战性

- 双 STM32U575 多任务实时调度。
- 上臂和手腕双 IMU 姿态同步。
- 可穿戴佩戴误差和姿态零点校准。
- 肌电弱信号采集、特征提取和模型泛化。
- LVGL 双端界面在 MCU 资源下稳定刷新。
- 无线串口、ESP8266、MQTT、HTTP 多链路协同。

### 作品价值

- 对患者：提供动作是否到位、次数是否完成、训练是否进步的即时反馈。
- 对康复师：提供训练历史、评分趋势和薄弱动作参考。
- 对居家康复：具备远程随访和长期数据追踪扩展基础。
- 对工程实践：体现软硬件一体化、边缘 AI 和嵌入式系统整合能力。

## 6. 最终总结话术

> AI-RehabBand 的创新性在于把双 IMU 相对姿态、肌电边缘 AI、动作状态机、双端本地界面和 Web 康复分析连接成了一个完整闭环；挑战性在于多传感器、多任务、多通信链路和可穿戴弱信号环境下仍要保持稳定；作品价值在于让居家康复训练从“凭感觉做动作”变成“有角度、有评分、有记录、有分析”的可追踪过程。
