# AI-RehabBand 智能康复臂带整合方案

## 1. 项目定位

**项目名称**：AI-RehabBand 智能康复臂带

**应用场景**：脑卒中患者上肢康复训练评估、居家康复动作指导、训练结果记录与反馈。

**核心目标**：面向脑卒中患者上肢康复场景，采用上臂 + 手腕双 6 轴 IMU 进行相对姿态解算，实现肘关节角度、角速度和角加速度的实时评估；参考无线 sEMG-IMU 论文中的双 IMU 段间角度估计、固定周期采样、零位校准和低带宽数据输出思路，但当前阶段不引入肌电采集模块；通过 STM32CubeAI 在 STM32U575 上部署小于 50KB 的轻量 CNN 模型，离线识别 6 类康复动作；以“完成度 + 平稳度 + 频率”三维指标量化康复质量，并通过双屏本地反馈形成完整训练闭环。

本方案主要沿用 `智能康复臂带1.0.md` 的双主控、双屏幕、双 IMU、CubeAI 动作识别、6 类康复动作和三维评分算法。`智能康复臂带-CubeMX配置方案.md` 作为 STM32U575RIT6 节点的底层硬件接口、外设配置和工程初始化依据：每个节点就近连接 1 个 IMU，复用同一套 SPI、LCD、UART、RTOS 配置思路。ADC 和肌电接口暂不作为当前整合方案的核心内容。

当前阶段先不加入语音交互、蓝牙 App 和肌电采集，避免现场调试复杂度过高；后期需要扩展一个交互 Web，用于训练数据查看、历史趋势展示和康复报告生成。

## 2. 总体方案概述

本作品采用双 STM32U575 同构双主控平台，分为上臂端和手腕端：

- **上臂端**：采集上臂 IMU 数据，承担主界面显示、训练过程展示和局部预处理。
- **手腕端**：采集手腕 IMU 数据，接收上臂端数据，完成相对姿态解算、动作识别、评分计算和实时反馈显示。

两端通过无线串口或其他低延迟无线链路同步传感器数据。系统通过上臂与手腕两个 IMU 的相对姿态计算肘关节角度，并参考论文中的固定周期采样与互补滤波思路，同步输出肘关节角速度和角加速度。动作识别部分基于 1 秒滑动窗口提取时域、频域、角度和角速度特征，输入轻量 CNN 模型识别康复动作。

核心能力包括：

1. 双 IMU 上肢姿态采集。
2. 肘关节角度实时解算。
3. 6 类康复动作离线识别。
4. 完成度、平稳度、频率三维评分。
5. TFTLCD + OLED 双屏本地反馈。
6. 固定周期采样、零位校准和低带宽数据输出。
7. 后期 Web 交互与康复报告扩展。

## 3. 系统架构

### 3.1 三层架构

| 层级 | 组成 | 作用 |
|---|---|---|
| 感知层 | 上臂 IMU + 手腕 IMU | 采集 6 轴运动数据 |
| 计算层 | 上臂 STM32U575 + 手腕 STM32U575 | 姿态融合、角度计算、AI 推理、评分 |
| 应用层 | TFTLCD + OLED + 后期 Web | 实时反馈、训练结果展示、历史数据分析 |

### 3.2 双主控数据流

```text
上臂 IMU
  -> 上臂 STM32U575
  -> 无线数据同步
  -> 手腕 STM32U575
  -> 姿态融合
  -> 相对姿态解算
  -> 特征提取
  -> STM32CubeAI CNN 推理
  -> 评分计算
  -> TFTLCD / OLED 显示
  -> 后期 Web 数据同步
```

### 3.3 双主控分工

| 节点 | 硬件 | 主要职责 |
|---|---|---|
| 上臂端 | STM32U575 + 上臂 IMU + TFTLCD | 上臂姿态采集、无线发送、主界面/训练曲线/历史摘要显示 |
| 手腕端 | STM32U575 + 手腕 IMU + OLED | 手腕姿态采集、接收上臂数据、相对姿态计算、AI 推理、实时评分反馈 |

手腕端作为主要算法节点更合适，因为手腕屏幕用于快速查看实时角度、动作和评分；上臂端 TFTLCD 负责更完整的信息展示。

## 5. CubeMX 配置原则

### 5.1 MCU 与时钟

```text
MCU: STM32U575RIT6
SYSCLK: 160MHz
Power Regulator Voltage Scale: Scale 1
Debug: Serial Wire
RTOS: CMSIS-RTOS v2
HAL Timebase: TIM17
```

160MHz 对姿态融合、特征提取、CubeAI 推理和屏幕刷新有足够余量；后期低功耗优化时可降至 80MHz。

### 5.2 IMU SPI 配置

```text
SPI1:
  Mode: Full-Duplex Master
  Hardware NSS: Disable
  Data Size: 8 Bits
  First Bit: MSB
  CPOL: High
  CPHA: 2 Edge
  Baud Prescaler: 32 或 64
  DMA: RX/TX Normal
```

IMU660RB 核心 LSM6DSRTR 常用 SPI Mode 3。每个节点只连接 1 个 IMU，通过本地 SPI1 稳定采样，再通过无线链路同步双端数据。

### 5.3 TFTLCD 配置

```text
SPI3:
  Mode: Transmit Only Master 或 Full-Duplex Master
  Hardware NSS: Disable
  Data Size: 8 Bits
  CPOL: Low
  CPHA: 1 Edge
  Baud Prescaler: 4 或 8
```

TFTLCD 以 P169H002 / ST7789T3 为参考，触摸 CST816D 使用 I2C1 400kHz。显示内容以文字、曲线和结果摘要为主，刷新频率建议 5Hz-10Hz。

### 5.4 UART 配置

```text
USART1:
  115200, 8N1
  双端数据同步或训练数据输出

USART2:
  115200, 8N1
  独立调试日志和参数下发
```

USART1 不建议持续发送完整 100Hz 原始数据。双端同步可发送压缩后的 IMU 帧、时间戳和校验；调试阶段再按需输出摘要。

### 5.5 FreeRTOS 任务建议

| Task | 优先级 | 周期/触发 | 职责 |
|---|---:|---|---|
| SensorTask | High | 100Hz | 读取本节点 IMU |
| LinkTask | High/AboveNormal | 100Hz 或事件触发 | 双端数据同步 |
| FusionTask | AboveNormal | 66Hz-100Hz | 姿态融合、相对姿态计算、角速度/角加速度计算 |
| FeatureTask | AboveNormal | 1s 窗口 / 10Hz 更新 | 提取角度、角速度、角加速度和 IMU 统计特征 |
| AITask | AboveNormal | 10Hz | CubeAI 推理，输出动作类别 |
| ScoreTask | Normal | 10Hz | 完成度、平稳度、频率评分 |
| DisplayTask | Low | 5Hz-10Hz | TFTLCD/OLED 刷新 |
| DebugTask | Low | 2Hz-10Hz | USART2 日志输出 |

优先级原则：采样和链路同步优先，姿态/角度计算其次，AI 和评分再次，显示和日志最低。

## 6. 核心算法

算法部分以 `智能康复臂带1.0.md` 的双传感器相对姿态解算为主线，同时吸收论文中双 IMU 段间角度估计的工程做法：固定周期采样、互补滤波、开机零位校准、角速度/角加速度派生和低带宽摘要输出。当前阶段不引入肌电模块，训练质量评分只基于 IMU 运动学特征。

### 6.1 姿态融合

每个 IMU 采集 3 轴加速度和 3 轴角速度：

```text
upper_arm: ax, ay, az, gx, gy, gz
wrist:     ax, ay, az, gx, gy, gz
```

使用 Madgwick AHRS 或互补滤波计算四元数姿态。论文中下肢深蹲方案采用加速度倾角 + 陀螺仪积分的互补滤波，本项目可先用互补滤波快速稳定角度，再逐步切换到四元数相对姿态：

```text
q_upper = 上臂姿态四元数
q_wrist = 手腕姿态四元数
```

IMU 采样频率建议 66Hz-100Hz，姿态融合同频运行。论文采用约 66.7Hz 固定周期即可稳定观察深蹲角度曲线；本项目上肢动作速度较低，MVP 可先采用 100Hz，若无线带宽或任务负载紧张，可降至 66Hz-80Hz。

### 6.2 相对姿态与肘关节角度

通过两个传感器四元数计算相对姿态：

```text
q_relative = conjugate(q_upper) * q_wrist
```

再将相对姿态转换为肘关节屈伸角度。为降低佩戴误差，每次训练前应在自然下垂或指定中立姿势保持 3 秒，记录零位 offset：

```text
elbow_angle = raw_relative_angle - zero_offset
0 deg: 手臂近似伸直
150 deg: 肘关节明显弯曲
```

角度指标包括：

- 实时肘关节角度。
- 单次动作最大角度。
- 角度变化范围。
- 角度达标次数。
- 角速度与平稳度指标。
- 角加速度峰值，用于识别动作突变和异常代偿。

### 6.3 角速度、角加速度与论文参考点

论文在膝关节深蹲任务中不仅显示角度，还同步显示角速度和角加速度，用于观察下蹲、最低点停顿和起身阶段。本项目可将该思路迁移到肘关节屈伸：

```text
elbow_velocity = (angle_now - angle_prev) / dt
elbow_acceleration = (velocity_now - velocity_prev) / dt
```

建议对角速度和角加速度做轻量平滑，避免差分放大噪声：

- 角度先低通，再求速度。
- 角速度再低通，再求角加速度。
- 评分中使用峰值、均方根和高频抖动比例，而不是直接使用瞬时最大值。

这些指标可以用于：

- 区分屈曲阶段、伸展阶段和停顿阶段。
- 判断动作是否过快。
- 判断是否存在突然抖动或代偿。
- 给平稳度评分提供更直观依据。

### 6.4 1 秒窗口特征提取

每 1 秒提取一次特征向量，可 10Hz 滑动更新。特征来源包括上臂 IMU、手腕 IMU 和肘关节角度。

| 特征类型 | 示例 | 说明 |
|---|---|---|
| 时域特征 | 均值、方差、峰值、峰峰值、RMS | 描述动作幅度和稳定性 |
| 频域特征 | 低频能量、中频能量、高频能量 | 描述动作节奏和抖动 |
| 角度特征 | 角度均值、最大值、最小值、范围 | 描述关节活动度 |
| 角速度特征 | 峰值、均值、RMS、正负峰位置 | 描述屈曲/伸展速度 |
| 角加速度特征 | 峰值、突变次数、RMS | 描述动作急停、抖动和异常代偿 |

特征向量维度可控制在约 100 维，作为 CNN 输入。

### 6.5 STM32CubeAI 轻量 CNN

模型部署目标：

```text
模型类型: 轻量 CNN / 1D CNN
模型大小: < 50KB
输入: 1 秒窗口特征
输出: 6 类康复动作概率
推理频率: 10Hz
目标准确率: > 90% 训练集/验证集，现场演示 >= 85%
```

推理流程：

```text
IMU 数据窗口
  -> 特征提取
  -> 归一化
  -> CubeAI 推理
  -> 6 类动作概率
  -> 置信度阈值判断
  -> 当前动作类别
```

置信度建议：

```text
max_prob >= 0.70: 接受识别结果
max_prob < 0.70: 保持上一状态或标记为未知动作
```

## 7. 康复动作

康复动作完全沿用 `智能康复臂带1.0.md` 的 6 类动作设计。

| 编号 | 动作 | 主要评估依据 | 康复意义 |
|---:|---|---|---|
| 0 | 前臂转动 | 手腕/前臂陀螺仪特定轴周期性变化 | 训练前臂旋前旋后能力 |
| 1 | 手臂外展 | 上臂姿态抬升，外展角度变化明显 | 训练肩关节外展能力 |
| 2 | 肘关节弯曲 | 上臂与手腕相对姿态变化，肘角范围 40-150 度 | 训练肘关节屈伸能力 |
| 3 | 腕关节旋转 | 手腕 IMU 高频旋转特征明显 | 训练腕部灵活性 |
| 4 | 肩上举 | 上臂姿态持续上升，角度范围较大 | 训练肩关节上举能力 |
| 5 | 步行平衡 | 上臂周期性摆动和稳定性特征 | 评估上肢摆动和平衡协调 |

其中肘关节弯曲是核心展示动作，因为它最能体现双 IMU 相对姿态测角的价值。

## 8. 康复质量评分

评分算法沿用 `1.0` 的三维指标：

```text
综合评分 = 完成度 * 60% + 平稳度 * 30% + 频率 * 10%
```

### 8.1 完成度

完成度衡量动作幅度是否达到目标区间。

示例：

```text
肘关节弯曲目标: 40 deg - 150 deg
实际最大角度越接近目标上限，完成度越高
```

完成度输出：

- 单次完成度。
- 平均完成度。
- 达标次数。
- 达标率。

### 8.2 平稳度

平稳度衡量动作过程中是否存在明显抖动、突变或代偿。

可参考指标：

- 角速度方差。
- 高频能量占比。
- 突变次数。
- 姿态曲线平滑程度。

平稳度越高，说明动作越可控。

### 8.3 频率

频率衡量动作节奏是否接近康复训练要求。

可参考指标：

- 单位时间动作次数。
- 动作周期稳定性。
- 与目标节奏的偏差。

频率评分不宜权重过高，因此保持 10%，避免患者为了追求速度牺牲动作质量。

## 9. 双屏交互设计

### 9.1 上臂端 TFTLCD

TFTLCD 作为主显示屏，适合展示完整信息：

- 首页和训练模式选择。
- 当前动作类别。
- 实时角度曲线。
- 完成度、平稳度、频率三维评分。
- 本次训练总分。
- 历史训练摘要。
- 系统设置和调试信息。

推荐页面：

```text
首页
训练页
结果页
历史页
设置页
```

### 9.2 手腕端 OLED

OLED 作为快速反馈屏，显示高频关键信息：

```text
实时角度
当前动作

连接状态
```

示例：

```text
120 deg
肘弯

```

OLED 刷新应保持轻量，避免影响手腕端 AI 推理。

## 10. 通信协议

### 10.1 双端同步数据包

上臂端向手腕端发送上臂 IMU 数据：

```text
ARM,tick,ax,ay,az,gx,gy,gz,checksum
```

二进制版本可进一步压缩：

```c
typedef struct {
    uint8_t header;      // 0xAA
    uint32_t tick;
    int16_t ax;
    int16_t ay;
    int16_t az;
    int16_t gx;
    int16_t gy;
    int16_t gz;
    uint8_t checksum;
} ArmImuPacket_t;
```

### 10.2 训练结果数据

训练结束后输出：

```text
RESULT,action,count,angle_max,completion,smoothness,frequency,total_score
```

示例：

```text
RESULT,2,12,146,92,81,88,88
```

后期 Web 可直接解析该数据格式，也可以由串口桥接程序转换为 JSON。

## 11. 后期交互 Web

当前阶段不做蓝牙 App，后期优先做本地交互 Web。Web 的定位不是云平台，而是演示和数据分析界面。

### 11.1 Web 功能

| 模块 | 功能 |
|---|---|
| 设备连接 | 通过串口桥接、局域网或 WebSocket 接收训练数据 |

| 历史记录 | 保存每次训练动作、次数、最大角度和总分 |

### 11.3 推荐实现方式


## 13. 验收指标

| 指标 | 目标值 | 说明 |
|---|---:|---|
| IMU 采样频率 | 66Hz-100Hz | 上臂端和手腕端固定周期稳定采集 |
| 双端同步延迟 | < 20ms | 满足相对姿态计算 |
| 肘关节角度重复性误差 | <= 5 deg | 同一动作多次测量，校准后统计 |
| 角速度/角加速度曲线 | 趋势稳定、无明显毛刺 | 能区分屈曲、伸展和停顿阶段 |
| 开机校准时间 | <= 3s | 建立 IMU 零位和关节角 offset |
| 6 类动作识别准确率 | >= 85%，目标 > 90% | CubeAI 离线识别 |
| CubeAI 模型大小 | < 50KB | 适配 STM32U575 |
| 推理频率 | 10Hz | 满足训练实时反馈 |
| 屏幕刷新 | TFT 5Hz-10Hz，OLED 10Hz | 不影响采样 |
| 综合评分输出延迟 | <= 300ms | 动作到反馈 |
| 连续演示时间 | >= 2h | 比赛现场稳定运行 |

## 14. 创新点表达

1. **双 IMU 相对姿态测角**：通过上臂 + 手腕两个 6 轴 IMU 的相对姿态，精准估计肘关节运动角度。
2. **陀螺仪运动学分析**：参考论文中的双 IMU 关节运动分析方式，同步输出角度、角速度和角加速度，用于识别动作阶段、过快运动和异常抖动。
3. **端侧 AI 动作识别**：使用 STM32CubeAI 部署小于 50KB 的轻量 CNN 模型，在本地离线识别 6 类康复动作。
4. **三维康复质量评估**：以完成度、平稳度、频率量化训练质量，比单纯计数更接近康复评估需求。
5. **双屏穿戴反馈**：TFTLCD 负责完整训练界面，OLED 负责实时角度与分数，兼顾展示性和穿戴反馈效率。
6. **Web 扩展能力**：后期通过本地 Web 实现实时曲线、历史趋势和康复报告，便于比赛展示和医生/家属查看。

## 15. 结论

整合后的 AI-RehabBand 以 `智能康复臂带1.0.md` 的技术路线为主体：双 STM32U575、双屏幕、上臂 + 手腕双 6 轴 IMU、肘关节相对姿态解算、角速度/角加速度运动学分析、STM32CubeAI 轻量 CNN、6 类康复动作识别，以及“完成度 + 平稳度 + 频率”的三维评分体系。

当前阶段先去掉语音交互、蓝牙 App 和肌电模块，把开发重点集中在双端数据同步、IMU 零位校准、角度/角速度/角加速度解算、AI 离线识别和双屏反馈上。后期再扩展本地交互 Web，用于实时数据可视化、历史趋势分析和康复报告生成。这样既保留 1.0 方案的完整性和创新表达，也能控制近期实现风险。
