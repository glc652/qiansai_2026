# 上臂端数据流

## 1. 总体链路

上臂端启动：硬件复位 → HAL/时钟/GPIO/通信外设初始化 → FreeRTOS 内核启动 → 采集、动作识别、显示和通信任务运行。

主链路：

```text
IMU/角度传感器 + EMG + 电池/连接状态
        ↓
I2C/SPI/ADC/串口等设备驱动
        ↓
采样缓存、滤波/标定、动作状态机
        ↓
角度/动作/次数/评分/完成度/肌电状态
        ↓
页面状态与通信打包
        ↓
Wi-Fi/ESP8266 或 MQTT/HTTP
        ↓
Web 服务与手机 APP
```

## 2. 任务与中断关系

以工程实际源码中的 FreeRTOS 任务、定时器回调、串口回调和通信打包函数为准；任务名、优先级和周期应结合 `F:\qiansai\upper-arm` 中对应函数核对。若答辩需要精确数字，必须引用源码中的 `xTaskCreate`、`vTaskDelay` 和中断回调，不能仅凭任务名推测。

## 3. 数据分支

- 动作分支：采样 → 角度/动作状态判断 → 计次和完成度 → 评分/结果页字段。
- EMG 分支：ADC/肌电采样 → 强度或模式判定 → 放松/较弱/用力 → 上送 `emg` 字段。
- 状态分支：电池、蓝牙/无线连接、手腕端状态和页面事件 → 组合进上送帧。
- 时间分支：设备时间/服务端同步 → 通信响应或本地时钟显示。

设备端具体滤波、阈值、动作识别公式、采样频率和传感器型号，必须以源码中的实际函数为证；未能定位的部分标记【无法确认】。

## 4. 输出与交互

上臂端 → Web：实时动作与训练数据；上臂端 ↔ 手腕端：连接状态和健康页面联动字段；Web/APP → 上臂端：若只有页面状态接口而无设备下发函数，则控制链【无法确认】。建议答辩用“采集层—算法层—应用协议层”三层图说明职责。
