# 1. 模块定位

本工程是智能康复臂带的手腕端固件，运行在 STM32U575RIT6 上。它负责：采集手腕 LSM6DSR 六轴 IMU；驱动 MKS142 健康监测模块；在本地完成姿态融合和健康帧解析；通过 USART1 将腕端姿态、加速度、角速度、心率和健康数据发送给上臂端；接收上臂端 ACK/训练/健康/回主页控制；同时提供本地 LCD、触摸、按键、振动和睡眠唤醒 UI。

它是腕端“传感与交互节点”，不是整个系统的主要动作识别/评分节点。实际动作融合与康复评分代码主要在上臂端；本端当前 `StartAlgoTask` 是空任务，`StartEmgTask` 也只是延时循环。

证据：`Core/Src/main.c:main`、`Core/Src/app_freertos.c:StartSensorTask`、`StartWirelessTask`、`StartHeartRateTask`、`StartDisplayTask`。

# 2. 硬件组成

| 模块 | 实际代码证据/用途 |
|---|---|
| MCU | `wrist.ioc`：`STM32U575RITx`/STM32U575RIT6；IOC 和时钟配置为 160 MHz，TrustZone disabled |
| 手腕 IMU | `lsm6dsr.c`：LSM6DSR，经 SPI1，PA5/PA6/PA7，CS 为 `IMU_WRIST_CS`；配置 208 Hz、±8 g、±2000 dps |
| MKS142 健康模块 | `mks142.c`、`mks142.h`：通过 USART2 接收 88 字节健康包，并发送采集开启命令；IOC 为 38400 8N1 |
| 上臂无线链路 | USART1，9600 8N1；`StartWirelessTask` 发送腕端/健康二进制帧并接收 ACK。代码注释称 HC-05，但具体模块型号需外部资料确认 |
| LCD | ST7789，经 SPI3；使用 DMA 传输处理函数和 `spi3LcdMutex` |
| 触摸 | CST816T，经 I2C1；触摸状态由 `CST816T_IsPressed` 等函数提供 |
| 电池 | ADC1 channel 15；`adc.c` 读取电压并按分压参数换算百分比 |
| 反馈/按键 | GPIO 振动马达、状态 LED、用户键、设置键 |
| EMG | ADC1 + TIM3 + GPDMA 的驱动代码存在，但当前 `StartEmgTask` 未启动实际处理；不能描述为当前手腕主功能 |

# 3. 软件架构

```text
HAL/CubeMX 外设初始化
  -> LSM6DSR / MKS142 / WirelessLink / LCD / CST816T / 电池 / 振动驱动
  -> SensorTask 姿态融合、HeartRateTask 健康数据、WirelessTask 打包通信
  -> DisplayTask 本地 UI 和 VibrationTask 反馈
```

RTOS 使用 CMSIS-RTOS2 API、FreeRTOS 内核。任务间主要通过全局快照加临界区传递：`wrist_imu_raw/euler`、`g_heart_data`、无线连接状态和页面请求均在 `taskENTER_CRITICAL` 保护下读写。消息队列用于振动脉冲；信号量 `mks142FrameSemHandle` 用于通知健康帧到达。

# 4. 上电初始化流程

1. `main` 调用 `HAL_Init()`。
2. `SystemClock_Config()` 打开 HSI/MSI/PLL，系统时钟配置为 160 MHz。
3. 依次初始化 GPIO、GPDMA、ICACHE、ADC1、SPI1、TIM3、I2C1、SPI3、USART1、UART4、USART2。
4. `osKernelInitialize()` 后调用 `MX_FREERTOS_Init()`：创建 UART/SPI/LCD/状态互斥锁、IMU/ADC 信号量、MKS142 帧信号量、消息队列和任务。
5. `osKernelStart()` 后任务接管执行。
6. `SensorTask` 反复初始化 LSM6DSR；通过 WHO_AM_I、软复位和寄存器配置完成启动；随后丢弃 100 点并采集 600 点陀螺零偏。
7. `DisplayTask` 初始化 LCD、CST816T、LVGL，显示启动 Logo 后建立主页。
8. `HeartRateTask` 初始化 MKS142 流式解析器，经 USART2 发送 `0x8A` 采集开启命令并挂起 1 字节接收。
9. `WirelessTask` 初始化协议，USART1 以中断方式接收上臂 ACK，并按 50 ms 周期发送姿态帧；健康模式下按 200 ms 发送健康帧。

# 5. 实时任务/中断

| 任务 | 优先级 | 周期/阻塞点 | 职责 |
|---|---|---|---|
| `SensorTask` | `osPriorityHigh` | 5 ms | LSM6DSR 采样、校准、低通和姿态融合；写本地 IMU 快照 |
| `AlgoTask` | AboveNormal | 1 ms 延时循环，但当前为空 | 预留算法任务，当前没有有效算法 |
| `EmgTask` | AboveNormal | 1000 ms | 预留 EMG 任务，当前不采集、不处理 |
| `WirelessTask` | Normal | `WRIST_WIRELESS_PERIOD_MS=50 ms` | 打包发送姿态；健康模式下 `WRIST_HEALTH_WIRELESS_PERIOD_MS=200 ms` 发送健康帧；接收 ACK |
| `DisplayTask` | Normal | 主循环 1 ms；睡眠轮询 50 ms；训练刷新约 220 ms；健康刷新 5 ms | UI、LCD DMA、触摸、按键、页面和休眠 |
| `DebugTask` | Low | 仅 `DEBUG_ANGLE_PRINT=1` 时创建 | 可选姿态调试输出 |
| `HeartRateTask` | 代码中创建；属性需以 `HeartRateTask_attributes` 为准 | 等待 MKS142 信号量，最长 2000 ms | 启停采集、读取健康快照、超时清除 |
| `VibrationTask` | BelowNormal | 等待振动队列 | 串行执行振动脉冲并清理积压请求 |
| `defaultTask`/`UiTask` | Normal | 当前没有创建 | CubeMX 占位任务 |

关键数据关系：`SensorTask -> wrist_imu_raw/euler -> WirelessTask/DisplayTask`；`USART2 ISR -> MKS142_FeedByte -> g_heart_data + mks142FrameSem -> HeartRateTask/ WirelessTask/DisplayTask`；`USART1 ISR -> ACK 状态和页面请求 -> DisplayTask`；`DisplayTask -> g_wrist_*_mode_active -> WirelessTask`。

中断/ DMA：TIM17 是 HAL time base，`main.c:HAL_TIM_PeriodElapsedCallback` 调 `HAL_IncTick`；USART2 RX 中断逐字节输入 MKS142 解析器；USART1 RX 中断解析上臂 ACK；SPI1 DMA 路径和 `imuDmaDoneSemHandle` 存在，但当前 `SensorTask` 使用阻塞式 `LSM6DSR_ReadRaw`；SPI3 LCD 使用 DMA 传输处理；ADC1 DMA 的半满/全满回调服务 EMG，但当前 EmgTask 不消费。未见 Wi-Fi、CAN、USB 或以太网协议栈。

# 6. 传感器数据处理链

## 6.1 IMU

`LSM6DSR_ReadRaw -> LSM6DSR_ParseRaw -> IMUProc_StateUpdate -> wrist_imu_raw/euler -> WirelessLink_BuildWristFrame/DisplayTask`。

SPI 读取 12 字节，小端解析陀螺和加速度，按 0.000244 g/LSB、0.070 dps/LSB 转换；启动静止校准累计 600 点平均陀螺 raw 偏置；`IMUProc_PrepareRawForUpdate` 对偏置附近 ±2 raw 设置死区；`IMUProc_StateUpdate` 扣除零偏、一阶低通 alpha=0.2，再执行六轴姿态融合。`IMUProc_AttitudeUpdate6Axis` 通过加速度重力方向叉积修正陀螺，Kp=1.0、Ki=0.05，积分单位四元数并转 roll/pitch/yaw。

## 6.2 健康模块

`MKS142` 约定每帧 88 字节、帧头 `0xFF`，内容没有再次出现 `0xFF`。`MKS142_FeedByte` 等待帧头，收满 88 字节后 `MKS142_ParseFrame` 提取 64 字节 PPG 波形、心率、SpO2、微循环、疲劳、收缩压、舒张压、SDNN、RMSSD。当前代码未在 MCU 内实现 PPG/血氧算法，健康指标来自 MKS142 模块输出。

收到有效帧后，USART2 回调更新 `g_heart_data`、`g_heart_valid`、`g_heart_last_frame_tick` 并释放 `mks142FrameSemHandle`。超过 `WRIST_HEART_DATA_TIMEOUT_MS=3000 ms`，HeartRateTask 清除心率和血氧为 0。

## 6.3 电池

`Battery_ReadMillivolts/Battery_ReadPercent` 启动 ADC1、轮询转换、读取 ADC 值，按 3300/4095 换算引脚电压，再乘分压系数；3.4 V 以下为 0%，3.9 V 以上为 100%，中间线性映射。UI 每 10 s 更新一次。

## 6.4 EMG（代码存在但当前未运行）

`emg_sensor.c` 实现 ADC DMA 64 点缓冲、半满/全满处理、2 秒静息 baseline、噪声标准差、包络 alpha=0.15、64 点 RMS、噪声 4 倍激活阈值和 strength 估计。但 `StartEmgTask` 只是 `osDelay(1000)`，且 `MX_FREERTOS_Init` 没有创建 EmgTask，因此只能标记为预留/未启用链路。

# 7. 核心算法

1. **IMU 姿态融合**：`Core/Src/imu_processing.c:IMUProc_AttitudeUpdate6Axis`。陀螺负责短期角速度积分，加速度重力方向负责滚转/俯仰校正，四元数避免欧拉角直接积分的奇异问题；无磁力计，yaw 长期漂移是已知限制。
2. **零偏校准与抗抖**：`StartSensorTask` 600 点均值校准，`IMUProc_PrepareRawForUpdate` ±2 raw 死区，`IMUProc_LowPassUpdate` 指数低通。
3. **MKS142 流式协议解析**：`mks142.c:MKS142_FeedByte` 以 0xFF 同步，帧内再次出现 0xFF 时重启同步；这是面向 UART 丢字节/错位的轻量状态机。
4. **无线帧编码**：`wireless_link.c:WirelessLink_BuildWristFrame/BuildHealthFrame` 按小端序写字段，并对除校验字节外的所有字段做 8 位累加和。
5. **UI 状态机与休眠**：`StartDisplayTask` 管理 HOME、WAIT_ARM、TRAINING、HEALTH 等页面，按触摸/按键/上臂事件切换；主页空闲 30 s 后关闭 LCD、背光并置 `g_wrist_sleeping`。
6. **当前没有本地康复动作识别/评分算法**：`StartAlgoTask` 是空循环；上臂端才有主要康复动作规则和评分。不能把腕端 UI 中的训练页面误称为腕端完成了动作算法。

# 8. 通信协议

## 8.1 手腕端 -> 上臂端普通姿态帧

接口 USART1，9600-8N1；`StartWirelessTask` 每 50 ms 发一帧。帧头 `0xAA`，总长 31 字节：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | `0xAA` |
| 1~2 | 2 | seq，小端 |
| 3~6 | 4 | tick，小端 |
| 7~12 | 6 | acc_mg[3]，int16，小端 |
| 13~18 | 6 | gyro_dps_x10[3] |
| 19~24 | 6 | angle_x100[3] |
| 25~26 | 2 | heart_rate |
| 27 | 1 | status：bit0 IMU 有效，bit1 心率有效 |
| 28 | 1 | battery_percent |
| 29 | 1 | status2：ACK、sleeping、battery valid、health mode、health enter/exit |
| 30 | 1 | 8 位累加校验 |

编码：`WirelessLink_BuildWristFrame`；校验：`CalcChecksum`，累加帧头至字段末尾。

## 8.2 健康帧

健康模式且数据有效时每 200 ms 发 17 字节，帧头 `0xAB`：`[1..2] seq`、`[3..6] tick`、`[7] heart_rate`、`[8] spo2`、`[9] micro_circ`、`[10] fatigue`、`[11] sbp`、`[12] dbp`、`[13] sdnn`、`[14] rmssd`、`[15] status`、`[16] checksum`。编码函数为 `WirelessLink_BuildHealthFrame`。

## 8.3 上臂端 -> 手腕端 ACK/控制

USART1 RX 逐字节由 `HAL_UART_RxCpltCallback` 处理。源码可确认的 ACK 解析内容：

- `A5 5A C3 3C`：普通链路 ACK；
- `A5 5A D4 4D`：训练开始；
- `A5 5A E5 5E`：回主页；
- `A5 5A F6 6F`：健康模式开始。

代码用状态机识别 0xA5、0x5A 以及后续控制字节，更新 `g_wireless_uart_ok`、`g_wrist_train_start_request`、`g_wrist_home_request`、`g_wrist_health_start_request`。上臂端如何发送这些控制帧可由上臂工程确认；手腕端源码只确认接收解析。

## 8.4 MKS142 UART 协议

USART2 38400-8N1；命令 `0x8A` 开启实时上报，`0x88` 停止，`0x98` 睡眠，`0x00` 唤醒。实时帧 88 字节、头 0xFF，无校验字段在本解析器中被验证；其可靠性依赖固定长度和帧内不出现 0xFF 的协议约束。

# 9. 与其他端的数据交互

```text
LSM6DSR -> SensorTask -> wrist_imu_raw/euler -> WirelessTask -> USART1 -> 上臂端
MKS142 -> USART2 RX ISR -> MKS142 parser -> g_heart_data -> WirelessTask -> 上臂端
上臂端 ACK/页面命令 -> USART1 RX ISR -> 页面请求标志 -> DisplayTask
DisplayTask 页面状态 -> g_wrist_training_mode_active / g_wrist_health_mode_active
```

普通姿态帧持续发送；健康帧只有健康页面/模式 active、数据未超时才发送。上臂端接收后可将两端姿态和健康数据用于康复训练/上传。手腕端自身的 `AlgoTask` 不生成动作评分结果。

# 11. 技术亮点

- **实时性**：SensorTask 5 ms 采样；无线姿态 50 ms、健康 200 ms；健康模块用中断逐字节接收而非阻塞整帧轮询。
- **可靠性**：IMU WHO_AM_I/软复位、600 点静止校准；无线帧固定长度+校验；MKS142 帧头错位重同步；3 s 健康数据超时清零；无线链路连接超时；UART 状态 ready 时自动重新挂接接收。
- **模块化**：IMU、MKS142、无线协议、UI、设置、振动分别独立文件；`MKS142` 解析层不依赖 HAL，便于单元测试和复用。
- **多源数据**：腕端将 IMU 与 MKS142 的心率/血氧/血压/HRV 指标统一封装后发送上臂端。
- **低功耗**：主页 30 s 无操作关闭 LCD/背光，设置 `g_wrist_sleeping`；睡眠时 HeartRateTask 停止等待/采集处理，健康和训练模式状态清除。MCU 是否进入深度低功耗不能由当前代码确认。
- **人机交互**：ST7789+LVGL、CST816T、用户键/设置键、夜间模式、振动提醒、训练/健康/断链页面。

# 12. 答辩值得讲的内容

1. 腕端作为独立实时传感节点：5 ms IMU 姿态更新，50 ms 姿态帧发送，避免把所有传感器数据都压到上臂端。
2. 六轴四元数融合和静止零偏校准，并主动说明无磁力计导致 yaw 漂移的边界。
3. MKS142 88 字节流式协议解析：帧头同步、固定长度、异常 0xFF 重同步、3 s 数据超时。
4. 自定义 31/17 字节二进制帧、定点缩放单位（mg、dps×10、角度×100）、累加校验、ACK/页面控制闭环。
5. UI 与通信协同：训练/健康页面改变模式标志，通信任务据此决定发送健康帧；断链页面和振动提示提升可用性。
6. 队列异步执行振动，避免 UI/通信任务直接阻塞较长振动时间。

# 13. 可能被评委追问的问题

1. IMU 配置 208 Hz 但任务固定 5 ms，是否存在采样频率不匹配、丢样或重复读？
2. 为什么当前使用阻塞式 `LSM6DSR_ReadRaw`，而不是已有的 SPI DMA 读函数？DMA 路径是否实际验证？
3. 没有磁力计时 yaw 如何长期校准？训练动作是否依赖绝对航向？
4. MKS142 的血氧、血压、疲劳、HRV 是模块内部算法输出还是本端计算？本端代码显示为前者。
5. MKS142 88 字节协议没有显式 CRC，帧内不允许 0xFF 的约束是否来自厂家协议？
6. 8 位累加和能检测哪些错误？为什么不采用 CRC16？
7. 无线 ACK 是 4 字节固定控制帧，是否存在误触发、丢字节和重发机制？
8. USART1 的连接模块是否确为 HC-05、实际吞吐是否足够同时发送普通帧和健康帧？【无法确认】
9. 为什么 `StartAlgoTask`、`StartEmgTask` 存在但当前为空/未创建？如何证明动作算法在上臂端而不是手腕端？
10. 进入睡眠后哪些外设仍运行？是否达到整机低功耗指标？【无法确认】
11. MKS142 无数据时，UI 如何避免显示旧心率？代码中通过 3 s 超时清零。
12. 全局快照是否都有临界区保护？是否会发生 UI、无线和健康任务同时读写导致撕裂？
