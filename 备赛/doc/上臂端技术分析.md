# 1. 模块定位

本工程是智能康复臂带的上臂端固件，运行在 STM32U575RIT6 上。它采集上臂 LSM6DSR 六轴 IMU 和 EMG，接收腕端 IMU/心率/健康数据，融合计算肘屈曲、前臂旋转、肩外展、肩抬举，完成重复次数与训练评分，并提供 LCD/触摸/语音/振动交互以及 ESP8266 Wi-Fi/MQTT 上传。代码中未发现康复执行器闭环控制，因此它主要承担感知、评估、交互和联网角色。

证据：`Core/Src/main.c:main`、`app_freertos.c:StartAlgoTask`、`StartWirelessTask`、`StartEspUploadTask`、`upper_ui.c:StartDisplayTask`。

# 2. 硬件组成

| 模块 | 实际代码证据和用途 |
|---|---|
| MCU | `upper arm.ioc`：`STM32U575RIT6/STM32U575RITx`，系统时钟配置/IOC 为 160 MHz，TrustZone disabled |
| 上臂 IMU | `lsm6dsr.c`：LSM6DSR，SPI1 PA5/PA6/PA7，CS 为 `IMU_ARM_CS`；208 Hz、±8 g、±2000 dps |
| EMG | `adc.c`、`emg_sensor.c`：ADC4 channel 2/PC1，默认 TIM3 TRGO + GPDMA circular，100 Hz |
| 电池 | `adc.c:Battery_ReadMillivolts/Percent`：ADC1 channel 15/PB0，按 3.3 V、12 bit、分压倍率 5 换算 |
| 腕端通信 | USART1，运行初始化实际为 9600-8N1；注释称 HC-05，接收二进制腕端帧 |
| Wi-Fi | USART2 115200-8N1；ESP8266 AT 指令、MQTT、HTTP |
| 显示 | ST7789，SPI3；LVGL 页面、训练和结果显示 |
| 触摸/语音 | CST816T 经 I2C1(PB6/PB7)；语音模块接 I2C2(PB10/PB14)，STM32 为从机 |
| 反馈 | GPIO 振动马达、蜂鸣器、LED；`vibration_motor.c` 提供脉冲/模式 |

注意：SPI1 DMA 读路径存在，但 `StartSensorTask` 实际调用阻塞式 `LSM6DSR_ReadRaw`，当前运行路径不能表述为“IMU 使用 DMA”。

# 3. 软件架构

HAL/CubeMX 外设层 -> LSM6DSR、EMG、WirelessLink、LCD/触摸/语音驱动 -> IMUProc/EMG/康复算法 -> RTOS 任务、UI、MQTT。

使用 CMSIS-RTOS2 API、FreeRTOS 内核。`MX_FREERTOS_Init` 创建任务、互斥锁、消息队列和信号量；实际主数据通道主要是全局快照加临界区，队列对象虽创建但当前业务路径未见作为主通道使用。

# 4. 上电初始化流程

`main` 执行：`HAL_Init` -> `SystemClock_Config` -> `MX_GPIO_Init`、ICACHE、GPDMA -> ADC1/ADC4 -> SPI1/SPI3 -> TIM3 -> I2C1/I2C2 -> USART1/USART2 -> UART4 -> `Vibration_Init`、`VoiceI2C_Init` -> `osKernelInitialize` -> `MX_FREERTOS_Init` -> `osKernelStart`。调度器启动后 main 的 while 不承担业务。

任务启动后：SensorTask 等待并初始化 LSM6DSR，再静止校准；DisplayTask 初始化 LCD/CST816T/LVGL、显示 Logo、加载历史；WirelessTask 开始 USART1 单字节中断接收；EmgTask 仅在准备/训练页面启用 EMG；EspUploadTask 延迟 8 s 初始化 ESP8266。

# 5. 实时任务/中断

| 任务 | 优先级 | 周期/触发 | 职责 |
|---|---|---|---|
| `SensorTask` | Realtime | 5 ms，约 200 Hz | LSM6DSR 采样、零偏、滤波、姿态；写 `debug_imu_raw/euler` |
| `AlgoTask` | AboveNormal | 100 ms | 读取上臂/腕端/EMG 快照，角度、动作、次数、评分；写训练快照 |
| `EmgTask` | AboveNormal | DMA 信号量；无信号 1 ms 检查；回退 10 ms | 启停 EMG、处理 DMA 半满/全满 |
| `WirelessTask` | Normal | 100 ms | 协议统计、取最新腕端帧、ACK、30 s 超时失效 |
| `EspUploadTask` | Low | MQTT 500 ms；健康至少 10 s | ESP8266、MQTT、HTTP 校时 |
| `DisplayTask` | Low | LVGL 5 ms；数据刷新 200 ms | LCD、触摸、按键、振动、休眠唤醒 |
| `DebugTask` | Normal | 100 ms | 语音命令；日志宏多数关闭 |
| `DataStreamTask` | Normal/100 ms | 当前 `EMG_CSV_STREAM_ENABLE=0`，不创建 | 可选 EMG CSV |
| `defaultTask`/`UiTask` | Normal | 宏关闭 | 当前不创建 |

数据链是 `SensorTask -> debug_imu_* -> AlgoTask`；`USART1 ISR -> WirelessLink -> WirelessTask -> latest_wrist_frame -> AlgoTask`；`ADC DMA ISR -> semaphore -> EmgTask -> Emg features -> AlgoTask`；`AlgoTask -> UI/Esp snapshot`。

中断/ DMA：TIM17 是 HAL time base，在 `main.c:HAL_TIM_PeriodElapsedCallback` 调 `HAL_IncTick`；TIM3 160 MHz/16000/100=100 Hz 触发 ADC4；USART1 RX 回调逐字节喂解析器并重启接收，错误回调清错恢复；ADC4 GPDMA 64 点循环缓冲，半满/全满释放 `adcHalfCpltSemHandle/adcCpltSemHandle`；SPI1 DMA 回调释放 `imuDmaDoneSemHandle`，但未被当前 SensorTask 使用；I2C2 事件/错误中断服务语音从机。未见 CAN、USB、以太网或蓝牙协议栈。

# 6. 传感器数据处理链

## 6.1 上臂 IMU

`LSM6DSR_ReadRaw -> LSM6DSR_ParseRaw -> IMUProc_StateUpdate`。SPI 读取 12 字节，小端解析后按 0.000244 g/LSB、0.070 dps/LSB 转物理量。SensorTask 先丢约 100 点，再累计 600 点算陀螺零偏；零偏附近 raw ±2 死区；`IMUProc_StateUpdate` 依次扣偏置、一阶低通(alpha=0.2)、六轴姿态融合。`IMUProc_AttitudeUpdate6Axis` 用加速度重力方向叉积修正陀螺，Kp=1.0、Ki=0.05，四元数积分/归一化并转 roll/pitch/yaw。

## 6.2 腕端

腕端已在另一节点完成采集/姿态处理；本端只解析 `acc_mg/gyro_dps_x10/angle_x100/heart_rate/status`。status bit0/bit1 和 30 s 超时控制有效性。

## 6.3 EMG

`TIM3 TRGO -> ADC4 -> GPDMA circular -> 半满/全满回调 -> EmgTask -> EmgSensor_ProcessSample -> GetFeatures -> AlgoTask`。启动后 warm-up 300 点，再用 200 个静息点估计 baseline 和噪声；`abs(raw-baseline)` 得 rectified，包络为 alpha=0.15 一阶滤波，RMS 为 20 点移动均方根。25 点窗口取第 5~95 百分位范围，15 个历史范围求稳定值；以静息范围 80%/20% 得 active/strength，连续 10 点进入、5 点退出，strength alpha=0.12 平滑。DMA 1 s 无样本或 6 s 未校准时切换软件 ADC 轮询。当前 `EMG_SENSOR_MODEL_ENABLE=0`，默认运行的是范围/滞回算法，不是模型。

## 6.4 融合

`AlgoTask` 首次收到有效腕端姿态记录肘相对 pitch、腕 roll、上臂/wrist pitch、上臂 yaw 零位。随后计算肘屈曲、前臂旋转、肩外展、肩抬举；计算肘角速度和 1 s 角度范围，加入 EMG active/rms、腕端心率等训练状态。

# 7. 核心算法

1. 姿态融合：`Core/Src/imu_processing.c:IMUProc_AttitudeUpdate6Axis` 是陀螺积分 + 加速度重力校正的互补/Mahony 风格算法。没有磁力计，因此 yaw 主要由陀螺积分，长期会漂移。
2. 动作判别：`app_freertos.c:Rehab_ClassifyRule` 是实际运行的规则阈值算法，结合角度、角速度、上臂稳定性和 enter/exit 阈值，动作锁存 1500 ms 抗抖。
3. 重复次数/评分：`rehab_eval.c` 的四个 `*Eval_Update` 为状态机：超过进入阈值进入，记录峰值，回到退出阈值且峰值足够时计数。默认目标 5 次。肘屈曲评分=完成40%+幅度40%+EMG参与20%；另三类=完成50%+幅度50%。
4. EMG 模型文件 `emg_participation_model.c`、`emg_rf_model.c` 被工程包含，但当前 `EMG_SENSOR_MODEL_ENABLE=0`；不能把它们说成默认运行算法。

# 8. 通信协议

## 8.1 腕端 -> 上臂

解析：`wireless_link.c:WirelessLink_PushByte`。帧头决定固定长度，校验为从帧头到校验前的 8 位累加和；错帧统计并重新同步。

普通帧头 `0xAA`、总长 31：`[0] header`；`[1..2] seq LE`；`[3..6] tick LE`；`[7..12] acc_mg[3] int16`；`[13..18] gyro_dps_x10[3]`；`[19..24] angle_x100[3]`；`[25..26] heart_rate`；`[27] status`；`[28] battery_percent`；`[29] status2`；`[30] checksum`。

健康帧头 `0xAB`、总长 17：`[1..2] seq`、`[3..6] tick`、`[7] heart_rate`、`[8] spo2`、`[9] micro_circ`、`[10] fatigue`、`[11] sbp`、`[12] dbp`、`[13] sdnn`、`[14] rmssd`、`[15] status`、`[16] checksum`。

## 8.2 上臂 -> 腕端

收到有效普通帧后 `StartWirelessTask` 发 4 字节 ACK：基本为 `A5 5A C3 3C`；训练开始 `A5 5A D4 4D`；回主页 `A5 5A E5 5E`；健康 `A5 5A F6 6F`。上臂源码只能确认发送内容，腕端如何解释需查看腕端工程。

## 8.3 Wi-Fi/MQTT/HTTP

ESP8266 经 USART2 收 AT 指令：`AT`、`ATE0`、`AT+CWMODE=1`、`AT+CIPMUX=0`、`AT+CWJAP`。源码自行构造 MQTT 3.1.1 CONNECT 与 QoS0 PUBLISH，经 `AT+CIPSTART`/`AT+CIPSEND` 发送。配置 host `10.35.253.211:1883`、client `upper-arm-001`；主题 `rehab/upper/realtime`、`rehab/upper/health`；实时 500 ms，健康 10 s 按 seq 去重。HTTP `10.35.253.211:5000/api/device-time` 用于校时。payload 是逗号 key-value 文本，不是 JSON：主页 `t,pg,ue,ub,wb,uba,wba`；训练 `pg,a,n,ang,e,ab,sh`；结果 `t,pg,a,n,g,s,m,av,em,e,ab,sh`。

# 9. 与其他端的数据交互

腕端 IMU/心率 -> USART1 二进制帧 -> 校验/快照 -> AlgoTask；本地上臂 IMU、EMG 同样进入 AlgoTask；AlgoTask 输出动作/评分/训练快照给 LVGL 和 ESP8266；健康帧在健康模式或上臂请求窗口内上传；断链 30 s 后腕端数据失效。语音模块经 I2C2 从机中断进入 `DebugTask`，触摸经 I2C1 进入 LVGL，UI 通过 LCD/振动反馈。

# 11. 技术亮点

- 实时性：Realtime IMU 5 ms，100 ms 算法环，EMG 硬件定时+DMA。
- 可靠性：WHO_AM_I/复位检查、校验和/重同步、30 s 超时失效、UART 错误恢复、EMG DMA 软件回退。
- 多传感器融合：上臂 IMU、腕端 IMU、EMG、心率/健康状态共同参与。
- 抗抖：陀螺死区、低通、EMG baseline/warm-up/百分位统计/滞回、动作锁存、稳定性约束。
- 模块化：驱动、协议、姿态、评估、UI、上传按文件/任务分离；快照、互斥锁、信号量隔离。
- 人机交互：LVGL、触摸、实体键、I2C 语音、振动、30 s 屏幕休眠。
- 低功耗意识：屏幕休眠关闭背光并停止 EMG；MCU 全系统低功耗模式未在当前代码确认。

# 12. 答辩值得讲的内容

重点讲“5 ms 姿态环 + 100 ms 康复算法环”；静止零偏、低通、六轴四元数；上下臂双 IMU 相对零位和四种动作角度；EMG 自校准、包络/RMS、范围统计、滞回和 DMA 回退；动作状态机、评分权重；二进制帧校验/超时/ACK；自行封装 MQTT 3.1.1 QoS0。CubeMX HAL、LVGL 第三方源码、字体和图片数组不值得展开。

# 13. 可能被评委追问的问题

1. IMU 为 208 Hz 而任务为 200 Hz，是否丢样/重复读？为什么不实际用已实现的 IMU DMA？
2. 六轴无磁力计，yaw 漂移如何影响动作？
3. 腕端掉线、佩戴姿态变化时零位如何处理？
4. 肩外展取上臂和腕端 pitch 变化的最小值依据是什么？
5. EMG 80%/20%、10 点/5 点阈值如何标定，电极极性变化是否适用？
6. 评分权重和目标角度是否有实验依据？是否支持个体化？
7. 8 位累加校验抗多比特错误能力有限，为什么不用 CRC？
8. MQTT QoS0 的断线、丢包、重连、重复上传怎样处理？是否有认证/TLS？
9. `upper arm.ioc` 记录了 ADC1/旧 DMA 配置，而当前源码使用 ADC4/ADC4 DMA，最终构建以哪一套为准？
10. 全局快照的临界区覆盖是否完整？阻塞式 UART 是否会影响高优先级任务？
